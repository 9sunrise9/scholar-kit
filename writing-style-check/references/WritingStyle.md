## Introduction

本文档定义中文学术写作正文的风格规范。文稿语言应保持严谨、客观、可验证，避免口号化、情绪化与口语化表达。

本规范以 PEP 8（Python 代码风格规范）为参照框架，将正文写作的各项要求分为五大类：

* **语言基调**：禁止表达、代词使用、数据引用
* **段落与句子结构**：主题句、判断句、列表引出、标点规范
* **技术内容组织**：介绍顺序、重点标注、交叉引用
* **内容完整性**：实质内容要求、字数目标
* **符号、格式与术语**：标点符号、缩写格式、括号限制

规范采用 **MUST**（必须）、**SHOULD**（应当）、**MAY**（可以）三级约束力标记。MUST 级条款违反即返工，无例外。

---

## Consistency

本节说明为何要保持一致性，以及何时可以例外。

### A Foolish Consistency is the Hobgoblin of Little Minds

学术文本的一致性直接影响可读性与论证可信度。统一语言风格比个人偏好更重要。

但本规范并非绝对律令。在以下情况下，撰写者可以合理偏离本规范：

1. 应用某条规定会使段落更难以理解时
2. 为与周围已确定风格保持一致时（尤其是引用已有段落时）
3. 有其他充分理由支持偏离时

**然而**：违反本规范铁律条款（MUST 级）不存在上述例外，必须严格遵守。

## Language Tone

本节规定正文语言的基调要求，包括禁止表达、代词使用和数据引用规则。

### Prohibited Expressions

正文 **MUST NOT** 使用以下类型的表达：

| 类别 | 禁止示例 |
|------|---------|
| 感叹式开头 | "在当今科技飞速发展……""随着人工智能浪潮席卷……" |
| 宏大叙事断言 | "引领第四次工业革命""重塑人类文明进程" |
| 文学化比喻 | "赋予设备灵魂""让机器拥有大脑""思考与感知的融合" |
| 能力堆砌句 | "不仅……更……还……"连续出现3个以上层进关系 |
| 演进式隐喻描述 | 用"走向""升级为""蜕变为""扩展到"描述技术范畴或能力变化 |
| 空泛定义句 | "该层的能力边界是……"后接可直接并入主句的动作描述 |
| 形态化套话 | "典型的硬件形态包括……软件形态包括……" |
| 模糊层级指代 | "上层""下层""平台层""设备层"等未指明具体层名的接口描述 |

```good
工业网络与边缘计算层由工业级边缘计算节点、实时工业交换机、时间敏感网络设备等硬件设备，以及轻量化推理引擎、流数据处理框架、实时操作系统等软件组件构成。
```

```bad
工业网络与边缘计算层典型的硬件形态包括工业级边缘计算节点、实时工业交换机、时间敏感网络设备。软件形态包括轻量化推理引擎、流数据处理框架、实时操作系统。
```

```good
该层与工业网络与边缘计算层的接口支持模型推送、性能反馈与效果评估；与数字孪生与决策联动层的接口支持决策方案生成与约束条件传导。
```

```bad
该层与上层的接口支持模型推送；与下层的接口支持执行落地。
```

```good
智能物联网（Artificial Intelligence of Things，AIoT）是将人工智能技术与物联网基础设施深度融合而形成的新型信息技术体系，其核心目标是赋予传统物联网系统自主感知、实时推理与闭环决策的能力。
```

```bad
在当今科技飞速发展的宏大叙事中，AIoT 已成为引领第四次工业革命的核心力量，深刻改变着人类生产生活的方方面面。
```

技术教材应以严谨客观的语言陈述事实，不以修辞代替技术内容。

### Pronoun Usage

指代非人物体、系统、概念、技术时，**MUST** 使用"它"，**MUST NOT** 使用"他"。

```good
智能制造是AIoT最成熟的应用领域，它主要通过在生产线部署传感器网络……实现生产全过程的智能化管控。
```

```bad
智能制造是AIoT最成熟的应用领域，他主要通过在生产线部署传感器网络……实现生产全过程的智能化管控。
```

### Colloquial-to-Academic Substitutions

写作过程中将口语化动词/短语替换为学术表达时，**SHOULD** 参照替换映射表：

- `references/lexicon-substitutions.zh-CN.json`

该映射表将原有替换规则结构化为可维护数据，便于复用、检索与自动化检查。映射使用要求如下：

1. **MUST** 结合语境选择替换，不做机械逐词替换。
2. **SHOULD** 优先使用可度量、可验证、可追溯的表达。
3. **MUST** 保持同段核心对象命名一致，避免同义词混用造成语义漂移。

代表性替换对示例：

| 口语 / 非正式表达 | 学术替换 | 说明 |
|------------------|---------|------|
| 出问题 | 失效 / 出现故障 | 依据对象选择“系统失效”或“节点故障” |
| 变差 | 下降 | 与指标搭配，如“准确率下降” |
| 吞吐 | 吞吐量 | 使用量化名词 |
| 鉴权 | 身份认证 | 安全语境统一术语 |
| 灰度发布 | 渐进式发布 | 工程部署语境更规范 |
| 打通 | 贯通 | 避免口号化表达 |
| 可落地 | 可执行 | 强调可实施与可验证 |
| 指的是 | 是指 | 规范定义句式 |

替换后须检查全段一致性，同一"产物"或"对象"在段内命名必须统一。

```good
其核心机制在于利用不同传感模态失效条件的差异性，以模态间物理量的互补覆盖消除单模态失效引发的感知盲区，从而提升复杂工况下的感知稳定性。
```

```bad
其核心逻辑就是用不同模态互相补位，哪里失效就靠别的模态顶上。
```

```good
跨域数据共享应先统一字段定义、单位标准和状态标签体系，再在分级授权与可追溯审计约束下实现受控共享。
```

```bad
跨域数据共享需要统一语义空间并保证一致性。
```

```good
工业网络与边缘计算层完成约束条件验证与安全身份认证，并通过任务调度接口与云计算与平台管理层协同。
```

```bad
工业网络与边缘计算层做了鉴权，并通过服务编排接口和上层联动。
```

```good
工业网络负责跨设备数据传输与时序一致性保障，并通过优先级调度机制满足确定性通信需求。
```

```bad
工业网络负责数据传输和时序保障，整体作为系统的数据通信底座。
```

```good
边缘节点通过离线容错保障策略维持异常工况下的基本服务能力，并将计算能力转化为可验证的持续运行能力。
```

```bad
边缘节点依靠离线可用策略，边缘计算才能把“可计算”转化为“可稳定运行”。
```

```good
机器学习通常分为监督学习、无监督学习和强化学习三种类型；新策略上线前应通过影子验证链路完成验证，并配套渐进式发布与回滚保障机制。
```

```bad
机器学习通常有几种方式；新策略先走影子链路，再灰度发布和回滚保护机制。
```

```good
数字孪生通过构建可同步更新、可计算推演的数字化孪生体，实现对物理系统状态与行为的持续映射与验证。
```

```bad
数字孪生通过构建数字化映射体，实现对物理系统状态与行为的持续映射与验证。
```

```good
数字孪生涉及的关键技术手段包括数据融合、模型构建、仿真推演、在线校准与闭环优化。
```

```bad
数字孪生涉及到的技术手段包括数据融合、模型构建、仿真推演、在线校准与闭环优化。
```

```good
预测性维护系统与生产节拍和交付可靠性直接耦合，是保障连续运行的运营保障模块。
```

```bad
预测性维护系统与节拍和交付稳定性直接耦合，是一个运营模块。
```

```good
安全控制机制应在架构设计初期嵌入，并与业务功能同步规划与验证。
```

```bad
安全控制机制应在架构设计初期纳入，再在后期逐步补齐实现细节。
```

```good
机器学习与智能控制技术用于统一模型决策与控制执行，并通过约束校核保障现场可执行性。
```

### Data Citation

凡引用统计数字，**MUST** 在同一句内标注来源机构与年份，格式为：

```
据[机构]统计，[年份]，……[引用标记]
```

```good
据IoT Analytics统计，2023年全球在网物联网设备数量达到163亿台，预计2025年将增至270亿台[1]。
```

```bad
预计到2025年，全球物联网设备数量将突破750亿台，产生的数据量更是无法估量。
```

## Paragraph and Sentence Structure

本节规定段落与句子的结构要求。

### Opening Sentence

每段**第一句**必须是判断句，直接陈述该段核心论点。

**MUST NOT** 以时间状语、条件状语或背景铺垫开头：

```good
边缘计算将数据处理能力从云端向网络边缘迁移，显著降低了端到端通信时延。
```

```bad
随着边缘计算技术的不断成熟……
在工业物联网快速发展的背景下……
```

### Section Lead-in Sentence

当段落位于某小节开头且承担“承上启下”作用时，**SHOULD** 在首段末句显式回扣本小节标题中的核心术语，说明该段工程矛盾与本节技术机制的对应关系。

```good
质量与规模之间的张力构成了群智感知系统的核心工程矛盾，也直接引出了本节的关键问题，即通过真值发现与可信融合机制在低可信输入条件下重建可用真值。
```

```bad
这一段和本节关系很密切，后面会讲怎么解决。
```

当小节开头承担“术语定义+意义延伸+发展脉络”功能时，**SHOULD** 采用“定义句→边界与作用句→演进句”三句式结构，避免只给名词解释而缺少工程语义与历史脉络。

```good
数字孪生是指以物理对象为参照构建可同步更新、可计算推演的数字化映射体。其意义不止于形成数字副本，还在于为运行分析、策略验证与风险预判提供全生命周期决策支撑。该技术由设备级仿真逐步演进到产线级与工厂级系统孪生，并与工业互联网、边缘计算和人工智能持续融合。
```

```bad
数字孪生就是现实系统在虚拟空间的一个模型，后面会继续介绍。
```

### Definitive Sentences

描述技术构成、定义、功能关系时，**SHOULD** 优先使用以下句型：

| 句型 | 用途 |
|------|------|
| ……是…… | 定义 |
| ……由……组成 | 构成 |
| ……包括…… | 列举 |
| ……分为…… | 分类 |

**MUST NOT** 连续使用"……可以实现……""……能够……""……支持……"超过2句。

```good
云端模式是指将数据采集设备获取的原始数据全部上传至云端服务器进行集中处理与推理的部署方式。
```

### List Introduction

正文出现4项及以上并列内容时，只有在以下情形下才**SHOULD**使用显式列表：内容构成稳定分类、教学上需要逐项对照、或各项之间需要保持平行结构。若若干内容只是对同一机制的连续补充、工程优化手段的并列说明，或作者为方便组织而临时命名的小标题，**SHOULD** 合并为一段，用"同时""此外""进一步""相应地"等连接词组织。

当确需使用列表时，**MUST** 用以下句式之一引出列表，**MUST NOT** 直接跟列表：

```
……主要包括以下X个方面：
……主要表现在以下几个方面：
……可分为以下X类：
```

当段落用于介绍“方法/方案/路线”时，**MUST NOT** 仅以并列名词或术语进行罗列；**MUST** 至少选取其中1-2个代表性方法，补充其适用场景、作用机制或约束边界，形成“方法名+为何有效+何处受限”的最小解释闭环。

当段落用于描述“挑战与应对”时，**MUST** 保持“问题-方法-缺陷”逐项对应结构：每个问题至少对应一种解决方法，并明确该方法当前的主要局限；**MUST NOT** 将问题清单与方法清单分离成两段独立罗列而缺乏映射关系。

```good
在安全防护方案中，零信任接入控制的关键在于将设备身份与最小权限策略实时绑定；软件定义分区与微隔离则通过缩小故障域限制横向渗透范围，两者分别作用于访问控制与扩散抑制环节。
```

```bad
安全防护可采用零信任、行为基线检测、微隔离、联邦学习与隐私计算等方法。
```

```good
针对低时延链路中的安全检测开销问题，可采用边缘轻量检测与平台深度分析协同方案；其局限在于边云阈值迁移不当时易出现误报波动。
```

```bad
当前问题包括时延冲突、身份伪造和供应链攻击。可用方法包括零信任、微隔离、联邦学习。
```

```good
低时延控制链路中的检测冲突可通过深度报文检测与边缘分层调度协同缓解，并在系统级约束下评估策略收益。
```

```bad
低时延场景下可使用深度包检测并解密加密流量以处理复合约束问题。
```

```good
AIoT的核心特征主要表现在以下几个方面：
1. 实时推理……
2. 自学习……
3. 分布式协同……
```

```bad
AIoT的核心特征包括：实时推理……、自学习……、分布式协同……
```

### Avoid Ad Hoc Enumerations

对非稳定分类、非标准术语、非教材必须逐项展开的内容，**MUST NOT** 生造枚举标签并逐项独立成段，例如"异步更新：""客户端选择："这类仅为叙述方便而添加的小标题。此类内容**SHOULD**回并到同一段中，通过逻辑连接词说明它们之间的递进、并列或补充关系。

同时，正文**MUST NOT**使用"总述句冒号 + 小标题冒号"的双冒号结构，例如"三种主要优化手段包括：\n\n梯度压缩：……"。应改为单段展开，或改写为"具体而言，……"后直接接续完整句。

```good
通信优化可从梯度传输、聚合时序和参与设备调度三个方面同时推进。其中，梯度压缩通过稀疏化或量化降低单轮上传数据量；异步更新通过取消全局同步等待提升异构设备环境下的训练吞吐量；而客户端选择则通过控制每轮参与设备集合压缩通信时延。
```

```bad
三种主要优化手段包括：

梯度压缩：……

异步更新：……

客户端选择：……
```

### No Colon-Listing Structure

正文 **MUST NOT** 使用冒号后接分号分隔的罗列句式，也禁止以"第一……第二……第三……""其一……其二……其三……"等显性序号标记展开并列论点。

三项及以上并列论点 **SHOULD** 合并为一段连贯叙述，各论点之间以实质性的因果、递进或对比关系自然衔接，而非依赖"在……方面""从……维度看"等归类标签进行段落过渡。关键要求是相邻句之间存在可辨识的逻辑推进（如"这一矛盾在……条件下进一步加剧""即便……，……仍难以……"），而非机械地将观点标签化后平铺。

```good
PPO在AIoT控制中的首要局限是样本效率较低——达到可用策略级别通常需要数十万至数百万次环境交互，工程上依赖高保真仿真预训练加真实环境微调的两阶段流程。训练数据充裕后，奖励函数的工程化设计构成另一重障碍：奖励稀疏或各分项权重不当会导致策略收敛至局部最优，需要领域专家反复调试。即便策略在仿真中收敛良好，其安全性仍难以获得形式化保证，工业部署时须在策略输出层叠加硬约束安全屏蔽层。
```

```bad
PPO在AIoT控制中的主要局限体现在以下三个方面。第一，样本效率仍较低。第二，奖励函数的工程设计困难。第三，策略安全性难以形式化保证。
```

```bad
PPO的局限表现在三个维度。从样本效率看……从奖励设计看……从安全性看……
```

```good
Koopman-MPC的工程局限首先表现在提升函数的选取缺乏系统性方法。这一精度与计算成本的矛盾在数据量有限时进一步加剧：EDMD在数据不足的情况下可能产生欠定问题，系统工作点超出训练分布时预测误差显著扩大。即便数据充分，提升维度远大于原始状态维度，二次规划规模随之平方增长。
```

```bad
Koopman-MPC的主要局限体现在以下三个方面。第一，提升函数选取缺乏系统性。第二，EDMD可能产生欠定问题。第三，提升维度导致计算量增长。
```

### Explanation Style

正文 **MUST NOT** 使用破折号或冒号引出的解释体写法来替代完整叙述，尤其应避免"术语——解释""概念：解释"这类机械结构。正文 **SHOULD** 写成语义完整、逻辑连续的句子，通过主谓宾关系和连接词自然展开技术含义。

```good
功能闭环能够让系统在运行过程中持续接收反馈，并据此修正模型参数和控制策略，因此模型性能可以在环境变化下保持稳定。
```

```bad
功能闭环：持续接收反馈并修正模型。
功能闭环——通过反馈更新模型参数。
```

**唯一例外**：纯技术参数符号（如量化精度 FP32→INT8）和图表图说（非正文散文）中可保留箭头符号。

```good
AIoT智慧医疗的技术框架分为四个处理层次：可穿戴传感器持续采集生理参数；采集数据经BLE或NB-IoT协议无线上传至网关；边缘节点对敏感数据执行隐私保护计算与本地预处理；处理后的特征数据提交云端AI诊断模型完成疾病分析与早期预警。
```

```bad
AIoT智慧医疗的技术框架为：可穿戴生理传感 → 无线数据传输（BLE/NB-IoT）→ 边缘端隐私保护计算 → 云端AI诊断模型。
```

## Technical Content Organization

本节规定技术内容的组织顺序与标注方式。

### Standard Sequence

介绍一项方法、技术或模型时，**MUST** 按以下顺序展开，不得颠倒：

```
1. 定义（中英文名称，一句话说明"是什么"）
2. 工作原理（说明"怎么运作"，可含公式或流程）
3. 系统组成（列出关键组件或模块）
4. 分类（如适用：主要类别及其特点）
5. 典型应用（至少一个具体实例，含量化效益指标）
6. 局限性（涉及方案评估或应用效果时 MUST 包含）
```

```good
云端模式是指将数据采集设备获取的原始数据全部上传至云端服务器进行集中处理与推理的部署方式。该模式的主要优点是计算资源充裕、模型训练与更新便捷；主要局限是数据传输时延较高（通常为数百毫秒至秒级），且原始数据离开设备后存在隐私泄露风险，不适用于工业实时控制场景。
```

```bad
云端模式的优势在于计算资源丰富、模型更新灵活，但其致命弱点是高延迟和隐私风险，这在工业实时控制场景中是不可接受的。云端模式是指……（先评价，再补定义）
```

需强调的内容，**MUST** 使用以下词语引出：

| ✅ 正确 | ❌ 禁止 |
|---------|--------|
| 特别指出，…… | 值得注意的是，…… |
| 需要说明的是，…… | 很重要的是，…… |
| | 不可忽视的是，…… |

### Cross-References

在同章节内部的前后引用，**SHOULD** 使用"如前所述"，**MUST NOT** 写出具体章节号（如"如第1章所述"），以保持各章独立性，避免读者跳读时产生断裂感。跨章节的显式引用仅在首次引出概念时使用。

```good
如前所述，传统物联网系统通常采用三层架构模型，由底至顶依次为感知层、网络层和应用层。
```

```bad
如第1章所述，感知层是物联网系统最底层的物理设备集合。（用于在同章节内回引前节内容）
```

### Avoid Redundant Summary Sentences

段末对段内已阐述内容进行再次归纳的总结句，**MUST** 删除，不得保留。段落以核心机制、数据指标或结论为结尾，无需用"因此/综上/由此可见"类句子重复已说内容。

```good
基于联邦学习，多个医院可在不共享患者隐私数据的条件下协同训练疾病预测模型，已有研究显示模型在跨机构数据集上的AUC较单机构训练提升约6%[X]。
```

```bad
……已有研究显示模型在跨机构数据集上的AUC较单机构训练提升约6%[X]。**由此可见，联邦学习在保护隐私的同时，实现了模型性能的有效提升。**（重复总结句，删除）
```

### Table References

引导读者查阅表格时，**SHOULD** 用简短句式"见表X. X"或将表格引用嵌入段落末尾，**MUST NOT** 使用"从A、B、C等N个维度对……进行了对比"的冗余导语。

```good
端层、边缘层与云层的能力对比见表7.2。
```

```bad
表7.2从计算能力、内存/存储、推理延迟、功耗和承担AI任务五个维度对端层、边缘层和云层进行了对比，供读者参考。
```

### Introductory and Review Sections

若某小节仅起"回顾"或"铺垫"作用，且其核心内容可在1–2句话内概括，**SHOULD** 删除该小节标题，将内容压缩为下一小节的首段过渡句，**MUST NOT** 为回顾内容单独保留一个完整小节。

```good
（7.2.2 开头）传统物联网采用感知层、网络层、应用层三层架构，集中式处理带来高延迟与大带宽消耗，感知节点也缺乏本地推理能力。针对上述局限，AIoT系统普遍采用云–边–端协同架构……
```

```bad

### 7.2.1 传统物联网三层架构回顾

如前所述，传统物联网系统通常采用三层架构模型……（整节只是为了引出7.2.2，内容可浓缩为一句过渡）
```

## Punctuation and Formatting

本节规定标点符号、格式与术语使用的具体要求。

### Chinese Punctuation

除数学公式（ `$...$` 和 `$$...$$` 块）内部以外，**MUST** 使用中文全角标点：

| 符号类型 | ✅ 正确 | ❌ 禁止 |
|---------|--------|--------|
| 引号 | `"……"`  `"'……'"` | `"..."`  `'...'` |
| 括号 | `（……）` | `(...)` |
| 冒号 | ： | : |
| 分号 | ； | ; |
| 逗号 | ， | , |
| 句号 | 。 | . |

### Quotation Mark Usage

正文中的引号**MUST** 使用中文弯引号，**MUST NOT** 使用英文直引号（ `"` ，U+0022）。

**中文弯引号字符**：

| 用途 | 字符 | Unicode |
|------|------|---------|
| 外层开引号 | `"` | U+201C |
| 外层闭引号 | `"` | U+201D |
| 内层开引号（嵌套） | `'` | U+2018 |
| 内层闭引号（嵌套） | `'` | U+2019 |

引号的适用场景仅限以下两种：

1. **术语强调**：首次引入非正式说法或特定用语时，如：形成感知–推理–决策–执行的完整闭环。
2. **直接引语**：引用他人原话或标准文献中的特定表述。

**MUST NOT** 将引号用于以下场景：

* 描述技术范畴或系统能力的升级/演进（见 L4）
* 代替括号说明术语
* 修辞强调（使用引号赋予词语"特殊含义"）

```good
1999年，Kevin Ashton提出物联网概念，强调设备之间的自动化信息交互。
系统决策依赖人工编写的规则，无法自动适应环境变化。
```

```bad
确立了"万物互联"的基本方向。（用引号包裹普通术语）
使物联网系统从"连接工具"升级为"智能系统"。（用引号强化比喻）
```

```good
联邦学习（Federated Learning，FL）
```

```bad
联邦学习（FL）
联邦学习FL
```

```good
直接使用：感知层、数据泄露、Q学习
```

1. 注明缩写全称（格式见上）
2. 补充数字参数

**MUST NOT** 用括号对前文的中文术语进行说明或重述：

```good
适应环境分布的变化，即发生概念漂移时也能自动调整。
采集心电、血氧、血压、血糖等生理参数。
```

```good
TensorFlow Lite（TFLite）
ImageNet数据集
NCNN（腾讯开源）
Cortex-A53@1.2GHz
```

正文段落中**MUST NOT** 使用 `**加粗**` 格式：

* 不得以段首加粗文字代替小标题
* 不得用加粗强调句中关键词
* 表题、图题等可正常使用格式

### Dash Separator

正文**MUST NOT** 以 `——` 破折号作为段落或内容之间的分节符。如需区分内容层次，改用分级标题或完整的段落过渡句。

### Pipeline Output Naming

描述多阶段流程（采集→推理→执行）时，**MUST** 在首次定义流程后为输出产物命名（如"决策动作""控制指令""推理结果"），并在后续句子中保持该名称一致，**MUST NOT** 用泛指词"产物""结果""输出"反复指代同一对象。

```good
前向回路输出决策动作。数据采集精度直接决定了推理结果的置信度上限……推理结果的到达时间超过控制周期……
```

```bad
前向回路输出了产物。数据采集精度直接决定了产物置信度上限……如果产物的到达时间超过控制周期……
```

### Colloquial-to-Academic Substitutions

描述系统或模型状态下降时，**MUST** 使用"性能退化"而非"退化"；描述信息层次时，**MUST** 使用"承担"而非"指的是"；描述技术挑战时，**MUST** 使用"涉及"而非"要处理/要在……中"。常见替换对照：

| 口语/模糊表达 | 学术规范表达 |
|-------------|------------|
| 退化 | 性能退化 |
| 整体效果变差 | 最终决策指令的精度与时效下降 |
| 指的是那几个模块 | 由……环节承担 |
| 要处理……问题 | 需完成……的可靠处理 |

### Section Lead-in Sentence

当一节的引言段仅起"列出后续各小节挑战/主题"作用时，**MUST** 将各子主题压缩成一句紧凑的并列说明，紧接"本节将围绕这X类技术展开"的承接句，**MUST NOT** 保留冗长的背景铺垫或将挑战逐条展开成段。

```good
AIoT功能闭环的稳定运行涉及五类核心技术挑战：感知层需处理多源异质数据的可靠融合，……分布式学习层还需在数据不出域约束下实现持续优化。本节将围绕这五类技术展开，重点讨论其工作机理以及它们如何对应解决前述工程问题。
```

```bad
【AIoT闭环稳定运行过程中，感知层要处理……这一部分简单写】本节将围绕……
```

## Violation Quick Reference

本节汇总常见错误，供快速核查使用。

| 编号 | 类别 | ❌ 错误 | ✅ 正确 |
|------|------|--------|--------|
| L1 | 宏大叙事 | "引领第四次工业革命" | 直接陈述技术事实 |
| L2 | 代词 | "他"指代系统 | "它"指代非人物体 |
| L3 | 数据来源 | "突破百亿台"无引用 | "据IoT Analytics统计，2023年……[1]" |
| L4 | 演进式隐喻 | "从'连接'扩展到'智能赋能'""升级为智能系统""走向万物智联" | 直接描述新增的具体技术功能，如"进一步集成了感知理解、在线学习与自主决策功能" |
| P1 | 段落开头 | "随着……"状语开头 | 判断句直接开段 |
| P2 | 列表引出 | 直接跟列表 | "主要包括以下几个方面：" |
| P2b | 不必要枚举 | 为行文方便生造"异步更新：""客户端选择："等小标题并逐项独立成段 | 合并为单段，用连接词说明并列或递进关系 |
| P2c | 双冒号结构 | "三种主要优化手段包括："后再接"梯度压缩：……" | 改为单段展开，或保留一个引导层级 |
| P2d | 序号/标签罗列 | "第一…第二…第三…""在XX方面…""从XX维度看…" | 合并段落，用因果/递进/对比句衔接，禁用归类标签过渡 |

## Section Heading and Structure

本节规定章节标题命名与小节数量的要求，适用于通用学术文稿的结构控制。

### Section Title Format

三级或四级小节标题 **MUST** 以"方法/技术+领域"命名，**MUST NOT** 将具体算法名罗列于标题。

| ❌ 含具体算法名的标题 | ✅ 方法/功能类标题 |
|---|---|
| 深度强化学习与近端策略优化 | 基于强化学习的控制 |
| 分布式共识协调算法 | 分布式多智能体一致性控制 |
| 数据驱动的模型预测控制 | 基于Koopman算子的数据驱动模型预测控制 |

* 当多个算法服务于同一控制目标时，标题取**控制目标或方法类**，具体算法名在正文段落中展开。
* 当节标题含技术框架名时，**SHOULD** 具体到核心方法而非泛化描述。

### Subsection Count Control

一个三级节（ `###` ）内的四级子节（ `####` ）**SHOULD** 不超过 3 个。若多个四级标题内容关联紧密，**SHOULD** 合并为一个标题，正文内用连接词或新起段落区分。

```good

#### Koopman算子理论及扩展动态模态分解

（将理论与数值方法合并，正文内先讲理论再讲EDMD）
```

```bad

#### Koopman算子理论

#### 扩展动态模态分解

#### Koopman-MPC控制框架

（三个独立四级标题拆分同一方法链的三步，过于细碎）
```

不构成独立知识单元的"控制框架""系统流程"等 **MUST NOT** 单独成节，应并入上文叙述。

### Typical Application Heading

若典型应用作为四级标题独立呈现，标题 **MUST NOT** 携带"典型应用："前缀，直接使用应用场景名称。

```good

#### 智能楼宇暖通空调节能控制

```

```bad

#### 典型应用：智能楼宇暖通空调节能控制

```

正文引出应用时改用句型："……的典型应用为……"。

## Citation and Attribution

本节规定正文内文献引用与研究归属的表达方式。

### No Inline Citation Marks

当文稿采用"文末统一参考文献"体例时，正文 **MUST NOT** 使用行内引文编号，如 `[112]()` 。参考文献信息在文末统一列出，不嵌入正文。

```good
Koopman算子理论提供了一种将非线性动力学在高维空间中精确线性化的数学框架。
```

```bad
受控系统的Koopman算子扩展由Korda和Mezić给出[112]()：他们将……
```

### No Author Attribution Sentences

在教材、技术报告与方法综述等体裁中，正文 **MUST NOT** 出现"由XX给出""由XX验证""XX等指出"等作者归属句式，正文应直接陈述技术事实。

```good
非线性MPC的在线优化问题计算量大，往往远超工业控制器的实时预算。
```

```bad
非线性MPC的在线优化问题的计算困难已由Korda和Mezić（2018）[112]()通过实验验证。
```

**唯一例外**：历史性事件（如"1999年，Kevin Ashton提出物联网概念"）可保留人名与年份，属于技术史叙述，不属于引文归属。

### No Mid-body Reference Section

当文稿采用"文末统一参考文献"体例时，各章正文末尾 **MUST NOT** 单独附"参考文献"节。

## Algorithm and Formula Expression

本节规定算法名称与公式引用方式。

### Algorithm Names

英文算法缩写或专有名称 **SHOULD** 使用国际通行的英文原名形式，不强制意译为纯中文。

| ❌ 意译/自造 | ✅ 通行英文原名 |
|---|---|
| Q学习 | Q-learning |
| 表格Q学习 | 表格方法（tabular method） |

当某算法已有广泛使用的中文名时（如"深度强化学习"），中文名优先，英文名括注；若中文名仅为直译且不通用，保留英文原名。

### Formula Reference in Body Text

公式参数说明 **SHOULD** 以"其中"引出，**SHOULD NOT** 频繁使用"式（X.X）"显式回引公式编号。

```good
其中$z_k = \psi(x_k)$为提升状态；$A$、$B$、$C$为待辨识的线性矩阵。
……上式等价于马尔可夫链……
```

```bad
式中，$z_k = \psi(x_k)$为提升状态……
式（3.12）的解退化为……
```

"上式"可在紧接公式的下一句使用；跨段落才需显式编号引用。

### Algorithm Introduction: No "Core Idea" Preamble

介绍某算法时，**MUST NOT** 使用"……的核心思想是：……"或"其基本设定是：……"等总述冒号结构，直接以该算法的行为主语展开叙述。（此规则与 P2c 双冒号规则一致，此处专针对算法介绍场景。）

```good
近端策略优化（Proximal Policy Optimization，PPO）……在每次策略更新时，通过裁剪概率比率来限制新旧策略的偏离幅度……
```

```bad
近端策略优化……PPO的核心思想是：在每次策略更新时，通过裁剪……
```

## Typical Application Writing

本节规定典型应用段落的写法。

### Introduction Sentence Format

典型应用段 **MUST** 以正文句式引出，不用独立标题或"典型应用：XX。"前置句。

```good
基于强化学习的控制的典型应用为工业机器人自适应路径规划。……
一致性控制的典型应用为分布式无线传感器网络的均值估计。……
```

```bad
典型应用：工业机器人自适应路径规划。……
典型应用：分布式无线传感器网络的均值估计。……
```

### Level of Detail

典型应用段 **SHOULD** 说明场景背景、方法选择理由、系统行为与核心效益，**SHOULD NOT** 逐一列出工程参数（如具体奖励数值、训练步数、状态向量维度等）。量化效益只保留最具代表性的 1~2 项。

```good
利用PPO算法在仿真环境中自主探索学习避障策略，无需精确地图即可在线决策。状态可以设计为激光雷达点云与目标位置相对坐标的拼接向量，动作设计为线速度和角速度的连续二维向量。奖励函数可以在到达目标点奖励、碰撞障碍惩罚与时间消耗惩罚间折中。
```

```bad
状态设计为激光雷达点云（720维）与目标位置相对坐标（2维）的拼接向量；奖励函数设计为：到达目标点给予正奖励10，碰撞障碍物给予负奖励-5……通过在ROS/Gazebo仿真环境中训练约$10^6$步后迁移至真实AGV，实测路径规划成功率可达97%，单次规划延迟低于50 ms。
```

## Process Description (Extended)

本节补充流程描述规范，面向多阶段流程的通用学术叙述。

### Staged Process Narration

描述多阶段工作流时，**MUST NOT** 在阶段名后接"依次包含以下步骤：……"的列举式结构；**SHOULD** 在阶段名后直接以连续句叙述，用"首先……其次……最后……"串联步骤。

```good
离线辨识阶段，控制器首先对系统施加激励信号采集数据对，选取提升函数集合，构造提升数据矩阵，最后求解最小二乘问题得到线性矩阵$A$、$B$、$C$。在线控制阶段读取传感器状态，计算提升状态，调用求解器求解，最后执行最优控制输入。
```

```bad
离线辨识阶段依次包含以下步骤：对系统施加激励信号……；选取提升函数集合；构造提升数据矩阵；求解最小二乘问题。
在线控制阶段依次包含以下步骤：读取传感器状态；计算提升状态；……
```

### Tool/Solver Names in Parentheses

正文叙述中，**SHOULD NOT** 在括号内注明具体开源工具或求解器的产品名，除非该工具本身是教学内容。

```good
可使用线性MPC求解器求解，计算复杂度与同维度线性系统的MPC相当。
```

```bad
可使用成熟的线性MPC求解器（如qpOASES）在毫秒量级内完成求解。
```

### Multi-Dimensional Problem Exposition（多维问题分层叙述法）

当讨论跨越多个维度或阶段的系统问题（如数据流通的安全威胁、系统架构的约束条件）时，**SHOULD** 采用"阶段分层法"而非"类别并列法"，以强化读者对问题演进的纵向理解。

**❌ 禁止**：按问题类别（威胁类型、约束属性）平行列举

```bad
威胁主要包括3种：
（1）类别A威胁
（2）类别B威胁  
（3）类别C威胁
```

**✅ 推荐**：按系统信息流的阶段（采集→传输→处理）分层叙述，每阶段说明该阶段特有的威胁及对应防护

```good
在**数据采集阶段**，设备直接获取敏感信息，主要威胁为……，防护手段包括……
在**数据传输阶段**，链路通信面临……威胁，差分隐私等技术可……
在**数据处理阶段**，云端或边缘侧面临……，同态加密等方案支持……
```

此法的优势在于：
* 强化读者对系统复杂性的分阶段认知  
* 便于后续补充阶段化的工程对策
* 避免过度的类别堆砌感

**应用场景**：7.5 节数据隐私与安全威胁章节（2026-05-07 新增）
